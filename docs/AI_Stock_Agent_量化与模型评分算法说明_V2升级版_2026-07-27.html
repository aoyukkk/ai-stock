1. 本轮升级解决了什么问题

2. 升级后的完整决策流程

Tushare 全 A 核心日线与基础数据 ↓ Point-in-Time、交易日、重复值、单位与行业主映射门禁 ↓ V2 Corrected Quant：技术 / 资金 / 情绪 / 动量 / 风险 ↓ 全市场 Top20 / Top50 / Top100 与数据置信度 ↓ Hard Gate（ST、停牌、不可交易、未来数据、重大黑天鹅） ↓ Flash 复核 → Pro 复核 → 人工关注股票合并 ↓ 市场状态与主题集中度限制 ↓ WATCH_POOL 与 ACTIVE_SHADOW ↓ 规则引擎生成参考价、止损、止盈与仓位建议 ↓ 第二轮 LLM 基本面补全 + 人工联网核验 ↓ 生成智能交易助手 Excel ↓ 同一候选集写入 Web 兼容数据链并自动发布 ↓ 交易员人工决策（系统不自动下单）

3. Quant 总分与五类因子

Quant Score = 25% × Technical 技术结构 + 25% × Capital 资金与成交 + 20% × Emotion 市场、行业与个股情绪 + 15% × Momentum 动量 + 15% × Risk 风险健康

100 分是理论上限，不是日常应达到的目标。各因子经过横截面标准化、风险约束和数据置信度处理， 要同时在五类维度都极强才可能接近高分。60—70 分通常已代表全市场中的相对优选， 不应以“是否接近 100”判断策略好坏。

3.1 Technical（25%）

  • 均线位置、趋势斜率、MACD、RSI、ATR、支撑压力与近期结构。
  • 专业因子缺失时使用本地历史重算，并标记 LOCAL_DERIVED 与技术置信度。
  • 技术强不等于当前可买，高位与部署风险由后续门禁处理。

3.2 Capital（25%）

  • 主力资金、成交额、换手率、真实量比、量价配合和流动性。
  • 正常缺失不再固定填 50，只对仍有效的资金子项重新归一化。
  • NON_RANDOM_MISSING、DATA_INSUFFICIENT 和 DATA_PIPELINE_ERROR 分开记录。

3.3 Emotion（20%）

本次最重要的算法变化之一，是把“所有股票共享一个市场情绪值”改为三层结构：

Emotion = 全局市场状态 + 所属行业/概念板块强度 + 个股相对板块强弱 − 情绪数据不完整的置信度折减
  • 全局层：上涨比例、涨跌停结构、全市场中位收益、成交与尾部风险。
  • 板块层：行业/概念涨幅、成分上涨比例、活跃度、持续性。
  • 个股层：个股相对行业和概念的强弱、是否与板块形成共振。
  • 因此同一天不同股票的情绪分应有差异，但仍受共同市场状态影响。

3.4 Momentum（15%）与 Risk（15%）

  • 动量关注 5 日、20 日收益及强度变化，不把末端急涨自动等同于好买点。
  • 风险健康分越高代表越安全；波动、回撤、高位拥挤、筹码、流动性和事件风险方向均按此解释。
  • 缺失数据不得提高风险健康分；硬风险直接进入 Hard Gate。

4. 数据门禁和降级原则

类别规则
必须数据 daily、daily_basic、stk_limit、adj_factor、正式行业映射、合法历史窗口
允许降级 moneyflow 按 S2.1；stk_factor_pro 本地重算；概念与 THS 资金缺失降低置信度
必须阻断 核心行情不完整、交易日不一致、未来数据、行业主映射大面积缺失、重复/单位错误、管线错误
数据来源 TUSHARE、IFIND、LOCAL_DERIVED 分别留痕，不混写

5. Flash、Pro 与人工候选如何组合

  • 量化分负责横截面排序；LLM 不改写 Quant 分数。
  • Flash 和 Pro 负责业务逻辑、催化、风险、证据置信度与持有期适配复核。
  • 人工关注股票与模型前 20 合并，不因“重点候选数量”被截断；人工股直接进入重点候选。
  • 全部人工关注股均进入 Flash 与 Pro 深度复核，包括不在 Quant 可评分 Universe 的 ST 股票。
  • ST 等 review-only 股票不补造 Quant 排名或分数，模型复核结果只用于风险解释；下单资格固定关闭。
  • 人工关注与量化同时入选的股票，仍按“人工关注”来源展示。
  • 人工候选没有模型分时保持未评分，不伪造 LLM 评分。

6. 市场状态与部署上限

2026-07-24 的市场状态为 RISK_OFF。高量化分不能绕过市场部署上限。 系统将研究候选拆分为：

层级作用本轮规则
WATCH_POOL保留研究和次日观察最多 10 只
ACTIVE_SHADOW用于前向影子跟踪，不代表真实下单RISK_OFF 时最多 2 只
BLOCKED / WATCH_ONLY受市场、风险、主题集中或可交易性约束不得因分数高而绕过

7. 第二轮基本面补全

  1. 读取第一次运行中已经形成的 Quant、Flash、Pro 和价格计划，不改写模型评分。
  2. 仅针对基本面信息不足或表达不完整的字段调用获准的 LLM 补全流程。
  3. 对仍需确认的信息进行人工联网核验，保存来源网址和证据记录。
  4. 最终在 Excel 与 Web 中展示主营业务、产业链、核心产品、概念、投资逻辑、财务状态和风险。
“补全”只增强可读性和证据质量，不允许 LLM 决定最终量化排名、挂单价格、仓位或交易数量。

8. Excel 与 Web 的统一机制

流程成功 ↓ 生成并校验 Excel（内容哈希 / 样式哈希 / 文件哈希） ↓ 将同一轮全量 Quant 与候选、基本面、价格计划写入数据库 ↓ 候选数 / Pro 数 / 价格计划数 / 仓位数强制对账 ↓ SQLite integrity_check = ok ↓ 原子替换 Web 只读业务数据库快照 ↓ Web 读取最新兼容运行

午盘双击流程、盘后正式流程、日常命令行流程以及 V2 修正版工作簿流程， 现在统一调用同一个发布服务。发布失败会在运行报告中显示 FAILED 并返回失败状态，不再静默保留旧网页数据。

10. 阅读结果时应注意

  • 分数是相对排序工具，不是上涨概率的直接百分比。
  • 同一市场状态会影响所有股票，但行业和个股层使 Emotion 不再完全相同。
  • 量化分高只代表相对更优，最终是否部署还要经过风险、市场状态和主题集中限制。
  • Shadow 候选用于验证，不代表买入建议；价格与仓位是规则化参考值。
  • 模型效果必须依靠 D1、D3、D5、MFE、MAE、超额收益、Rank IC 等前向结果判断。
本轮升级结论： 数据缺失处理、情绪差异化、基本面补全和 Web 发布链路已经形成统一闭环； 正式生产算法与交易安全边界保持不变，V2 继续以 Shadow 方式前向验证。
